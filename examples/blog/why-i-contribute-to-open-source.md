## The Best Code I've Written Was for Someone Else

A few years ago I fixed a small bug in an open source library I depended on. It took an afternoon. The maintainer merged it the next day and thanked me in the release notes.

That tiny interaction changed how I think about software.

## You Learn Faster From Real Code

Tutorials are sanitised. Real codebases are not. They have edge cases, legacy decisions, and comments explaining why something works the way it does. Reading and contributing to production open source code teaches you things no course can.

## It Compounds

Your fix helps everyone using that library. Their improvements come back around. The whole ecosystem moves forward together.

This is obvious when you say it out loud, but it's easy to forget when you're heads-down in a sprint.

## Where to Start

Don't start with a massive project like React or Linux. Find something small that you actually use. Look for issues labelled `good first issue` or `help wanted`.

Even documentation improvements count. Fixing a confusing README is a real contribution.

## It Doesn't Have to Be Code

Opening a detailed, reproducible bug report is valuable. Writing a how-to guide is valuable. Answering questions in a project's discussion forum is valuable.

Contribution is anything that moves the project forward. Start there.
